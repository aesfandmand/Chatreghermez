# چک صفحهٔ استرابورد — strabord-v2

**تاریخ:** ۱۰ مرداد ۱۴۰۵ · **وضعیت:** BLOCKER در هر دو دروازه
**روش:** مسیرها و اندازه‌ها از خودِ سورس خوانده شده. اعداد فونت در این
صفحه `clamp()` نیستند و مقدار ثابت دارند، پس خواندن از سورس دقیقاً برابر
اندازه‌گیری در مرورگر است. ردیف‌هایی که رندر لازم دارند علامت خورده‌اند.

---

## بخش ۱ — ممیزی مسیر: BLOCKER

از ۳۷ مسیر داخلی رندرشده، **فقط ۳ تا** در قرارداد v4.2 ثبت‌اند.
**۳۴ مسیر ثبت‌نشده و ۳۴ نقض trailing slash.**

### بدترین مورد: خودِ آدرس صفحه ثبت نیست

```html
<link href="https://chatreghermez.com/structures/strabord" rel="canonical"/>
```

`/structures/strabord` در قرارداد وجود ندارد. آنچه ثبت شده این است:

```
/products/outdoor-structures/straboards/
```

یعنی canonical صفحه به مسیری اشاره می‌کند که معماری نمی‌شناسد، و
`/structures/` هم به‌عنوان ریشهٔ عمومی اعلام نشده. Breadcrumb اسکیما هم
همان `/structures` را می‌زند. این از دستهٔ لینک اشتباه نیست؛ **هویت خودِ
صفحه است.**

### بقیه

- **۱۰ مورد فقط اسلش:** `/blog` `/consulting` `/faq` `/portfolio` `/printing`
  `/privacy` `/terms` `/services/outdoor-advertising` `/services/urban-investment`
- **۲۴ مورد اصلاً ثبت‌نشده:** همان دستهٔ صفحهٔ سرمایه‌گذاری، به‌علاوهٔ
  `/structures` و `/structures/lightbox` و `/structures/strabord`.

## بخش ۲ — سه ایراد که ربطی به قفل‌ها ندارد و باید بسته شود

### ۱· شمارهٔ تماس پاورقی جعلی است

```html
<a href="tel:+989000000000">۰۹۰۰ ۰۰۰ ۰۰۰۰</a>
<a class="cgm-ch-item" href="https://wa.me/989000000000">واتس‌اپ</a>
```

هدر شمارهٔ واقعی `۰۳۱-۳۶۲۵۸۳۱۰` را دارد، ولی پاورقی و واتس‌اپِ پاپ‌آپ
تماس هر دو `۰۹۰۰۰۰۰۰۰۰۰` هستند. یعنی دو مسیر از سه مسیر تماس صفحه، به
جای خالی می‌روند.

### ۲· چهار لنگر مرده

| لینک | مقصد | روی این صفحه |
|---|---|---|
| لوگوی هدر | `#hero` | وجود ندارد |
| «درباره ما» | `#about` | وجود ندارد |
| «مجله و ویدئو» | `#media` | وجود ندارد |
| پاپ‌آپ «انتخاب نیاز» | `#query` | وجود ندارد |

کلیک روی لوگو هیچ کاری نمی‌کند. لوگو باید به `/` برود، نه به لنگر.

### ۳· لوگوی پاورقی ۴۰۴ می‌شود

```html
<img src="./logo(1).png"/>
```

مسیر نسبی است. روی `/structures/strabord` به
`/structures/logo(1).png` حل می‌شود که وجود ندارد. هدر از base64 استفاده
می‌کند، پاورقی از فایل. پرانتز در نام فایل هم باید برود.

## بخش ۳ — ترجمهٔ بازخورد مالک (قفل ۱۰)

> «این صفحه اصلا خوب نیست نه سایز نوشته‌ها و نه دیزاین.
> حتی متناسب با نیاز کاربر هم نیست.»

طبق قفل ۱۰ این بازخورد مستقیم اجرا نمی‌شود. ترجمه‌اش این است:

### الف · «سایز نوشته‌ها» → پلهٔ میانی وجود ندارد

اعداد واقعی، از سورس:

| عنصر | موبایل | دسکتاپ ≥۹۰۰ | قفل ۶ |
|---|---|---|---|
| `h1` | ۳۱px | **۴۳px** | ۴۳px ✓ |
| `h2` (`.sb3-h`) | ۲۴px | **۳۱px** | ۲۸px ✗ |
| **`h3`** | **ندارد** | **ندارد** | ۱۹٫۵px ✗ |
| متن (`.sb3-p`) | ۱۶px | **۱۵٫۵px** | ۱۶٫۵px ✗ |

**H1 دقیقاً روی عدد قفل است.** پس ایراد از درشتیِ تیتر نیست.

ایراد این است که **صفحه هیچ H3 ندارد.** نردبان از ۳۱px یک‌باره می‌افتد
به ۱۵٫۵px. نسبت پله: **۳۱ ÷ ۱۵٫۵ = ۲٫۰۰**، در برابر سقف ۱٫۵۵ قفل ۶.

هرچه در این صفحه نقش تیتر فرعی دارد — نام اجزای سازه، عنوان مراحل، تیتر
کارت‌ها — با `<b>` نوشته شده در ۱۵ تا ۱۶٫۵ پیکسل، یعنی هم‌اندازهٔ متن
عادی. چشم هیچ پله‌ای بین «عنوان بخش» و «متن» نمی‌بیند، و همین حس
بی‌نظمی و درشتی می‌دهد.

این همان مثال خودِ قفل ۱۰ است:

> «فونت درشت است» را «H1 را کوچک کن» فهمیدیم، در حالی که مسئله
> **نبودِ پلهٔ میانی** بود.

**ترجمهٔ عددی:** افزودن تراز H3 در ۱۹٫۵px، بردن متن به ۱۶٫۵px، و
پایین‌آوردن H2 به ۲۸px. نتیجه: ۴۳ ÷ ۲۸ = ۱٫۵۴ · ۲۸ ÷ ۱۹٫۵ = ۱٫۴۴ ·
۱۹٫۵ ÷ ۱۶٫۵ = ۱٫۱۸. **H1 دست نمی‌خورد.**

### ب · «دیزاین» → سه سیستم بصری روی هم

صفحه هم‌زمان سه دستگاه CSS دارد که دو تایش اصلاً استفاده نمی‌شود:

| لایه | وضعیت |
|---|---|
| `.sb3-*` | سیستم فعال صفحه |
| `.ps-*` | کل سیستم بصری نسخهٔ ۲، **مرده** |
| CSS صفحهٔ خانه (`.hero-*`، `.query-*`، `.route-*`، `.hub-*`، `.process-*`، `.portfolio-*`) | **مرده** |

به‌علاوه بلوک «v5 refinement patch» **سه بار عیناً تکرار شده**،
`.slot-fact` دو بار با رنگ متناقض تعریف شده، و یک بلوک بزرگ جاوااسکریپت
صفحهٔ خانه در `try/catch` مهار شده تا خطایش صفحه را نخواباند.

**ترجمهٔ عددی:** حذف CSS و JS مرده، یک تعریف برای هر کلاس، و توکن رنگ از
`:root` به‌جای `--sb-*` محلی. سنجه: صفر قاعدهٔ تکراری، صفر بلوک
`try/catch` برای مهار کد بی‌ربط.

### پ · «متناسب با نیاز کاربر نیست» → مهم‌ترین ایراد

این ایراد از آن دو بزرگ‌تر است. کامنت بالای خودِ فایل مخاطب را تعریف
کرده: **شهرداری، سازمان دارای مجوز نصب، سرمایه‌گذار.**

ولی صفحه برای این مخاطب ساخته نشده:

| چیزی که ساخته شده | چیزی که آن مخاطب لازم دارد |
|---|---|
| پیکربند قیمت با **«افزودن به سبد خرید»** به‌عنوان دعوت اصلی | پیش‌فاکتور رسمی و مدارک مناقصه |
| مناقصه در یک کادر خط‌چین کوچک، کنار | مسیر اصلی صفحه |
| جدول مشخصات فنی با **۱۱ ردیف** | همان جدول، **پرشده** |

و نکتهٔ تعیین‌کننده: **همهٔ اثبات‌های این صفحه خالی‌اند.**

```
SPEC-01 … SPEC-11   جنس اسکلت، ضخامت ورق، مقاومت باد، ارتفاع کل …
FCT-01, FCT-02      زمان تحویل، مدت ضمانت
PRT-01, PRT-02      دو نمونه‌کار
```

پانزده جای خالی. یعنی کارشناس فنی شهرداری که برای ارزیابی تأمین‌کننده
وارد صفحه می‌شود، در بخشی که صفحه خودش اسمش را گذاشته «آنچه برای بررسی
فنی و پیوست مناقصه لازم دارید»، **یازده کروشهٔ خالی می‌بیند.**

صفحه یک سبد خرید کامل دارد برای مخاطبی که هرگز از سبد خرید استفاده
نمی‌کند، و جدول مشخصاتی خالی دارد که تنها چیزی است که آن مخاطب می‌خواهد.

### ت · قفل ۲ نقض شده — بند صفر

**صفحه هیچ بخش شکستی ندارد.** قفل ۲ صریح است:

> از این پس بند صفر است: هیچ صفحه‌ای بدون بخش شکست تحویل نمی‌شود.
> حداقل سه محور، پیش از بخش راه‌حل.
